## Findings from this pass

- The upstream example does reproduce after clipping our raw inference result to [-1, 1]: correlation is above 0.99999999999, RMSE about 0.00000122. Roughly 38.32% of raw samples exceed that range. Clipping is a serious playback/quality risk, though the match resolves the previous checkpoint/demo discrepancy.
- The model is still noncausal and supports a single enrollment target per inference. Two selected speakers require a separate, measured system design.
- The scoring contract supports a list of selected speaker IDs and a combined clean reference; its synthetic check covers both two-speaker/single-selection and three-speaker/two-selection cases.
- One 16 kHz clean Libri2Mix test mixture was generated from pinned official metadata and verified LibriSpeech audio. Selecting speaker 4077 yielded **+10.57 dB SI-SDRi**; selecting speaker 5142 yielded **+1.14 dB**. Both raw outputs exceed playback range. These two trials share one mixture and do not establish a general performance score.
- The user heard the 4077 fixed-gain output as cleaner than the 5142 fixed-gain output. This is one listening impression, consistent with the measured difference on that mixture.
- A matching clean Libri3Mix trial added speaker 5683. The checkpoint requested for 5142 produced an output much closer to 5683 than 5142. Directly summing two extracted voices yielded SI-SDR improvements of **+0.46, -0.62, and +0.90 dB** across the three possible selected pairs. These are all selections of one mixture; see the [M2 interim report](evaluation/M2_INTERIM_REPORT.md).
- In the 4077+5142 pair output, the user heard unselected 5683 overpowering the chosen voices and found 5142 unclear. This pair fails the desired listening outcome on this example; changing the uniform preview gain cannot repair that speaker confusion.
- A pinned Apache-2.0 SpeechBrain Libri3Mix SepFormer checkpoint was added as a blind-separation-plus-enrollment-matching comparator. On the user's 4077+5142 clip, its mixture-fit combination reached **+19.68 dB SI-SDRi at a common 8 kHz score rate**, versus **+0.48 dB** for the SpeakerBeam-SS sum. It is offline, 8 kHz, fixed to three output streams, and noncausal.
- The user listened to the SepFormer 4077+5142 and 5142-only outputs and reported that SepFormer seems to split and select the voices well on this original three-voice example. The 5142-only extraction reached **+23.23 dB SI-SDRi** at the common 8 kHz score rate. See [listening files 04 and 09](evaluation/data/listen_next).
- On four initial three-speaker clips (12 selected pairs), SepFormer with the original Resemblyzer matcher had a **+12.94 dB median** but improved only **7/12** pairs; matching was correct for **6/12**. A pinned ECAPA matcher, using the same cached separated streams, matched **12/12** and improved **12/12** on that set.
- On four new speaker-disjoint holdout mixtures (12 new selected pairs), ECAPA matched **12/12** correct streams and all **12/12** pairs improved, with **+15.25 dB median** SI-SDRi at 8 kHz. The original matcher matched 7/12 on this holdout. This is still a small clean-speech sample.
- The user's real stereo 48 kHz recordings (`Mix.wav` plus one separate enrollment for Nicker, Mond, and Sam) were located and run through the offline SepFormer + ECAPA pipeline. Six 23.13-second single- and two-speaker listening outputs are in [local results](evaluation/data/user_recordings/results). The originals were not altered. No same-take clean references exist for objective SI-SDR scoring; user listening is the next quality check.
- A controlled turn/absence clip gave **-37.1 dB** output energy during the 5683-only interval relative to selected-only intervals for SepFormer mixture-fit, versus **+7.1 dB** for SpeakerBeam-SS sum. This is one synthetic speaking pattern, not real-room validation.
- A [causal SepFormer diagnostic](evaluation/CAUSAL_SEPFORMER_EXPERIMENT.md) tested attention masking alone and masking plus local normalization without retraining. Masking alone still depended on future audio; masking plus local normalization reduced prefix dependence to an observed 8-sample boundary effect, but mean oracle SI-SDR on one clean three-speaker mixture fell from **15.44 dB to −4.28 dB**. A 250 ms segment took **343 ms** to compute on this machine. This converted checkpoint is not suitable for the live app.
- A [wall-clock-paced Mix.wav simulation](evaluation/REALTIME_SIMULATION.md) released 20 ms frames and measured SepFormer + ECAPA over non-overlapping windows. With 500 ms windows, virtual playback delay was **1.018 s median / 1.222 s p95**, four of 46 full-window processing calls exceeded 500 ms, and playback gaps totaled **289 ms**. With 1 s windows, delay was **1.581 s** and playback gaps totaled **7.81 ms**, with zero of 23 full-window processing budget misses. The 23 s simulation does not measure physical audio routing or establish sustained mobile streaming. Speaker quality on these short windows requires listening.
- The user listened to the windowed live-replay results and found them worse than full-recording SepFormer. This windowed configuration fails the desired listening outcome on the local recording. Short-window ECAPA similarities are also lower, but no clean references are available to isolate separation versus speaker-matching errors. Full-clip SepFormer remains the offline quality reference.
- A [rolling-context experiment](evaluation/ROLLING_CONTEXT_EXPERIMENT.md) replays the same Mix.wav with a fixed 500 ms hop and 2,500 / 1,000 / 500 / 250 ms of retained past audio. Only the newest hop is emitted; no extra lookahead, crossfade, model changes, or datasets were added. Steady full-pipeline processing medians were **1,131 / 715 / 560 / 480 ms**. The 250 ms context is the fastest candidate but exceeded its 500 ms budget on **8/45** steady full hops and had **1.065 s p95 virtual playback delay**. All longer contexts exceeded every steady-hop budget. All 108 output/comparison WAVs, timing boundaries, timeline gaps, and original input hashes passed verification. **Listening quality and the shortest acceptable context remain pending**; a local comparison page includes full-recording and prior no-context outputs.
- An additional **1,500 ms past context + 500 ms new audio** replay completed using the same pipeline (2 s total window). Steady processing was **846 ms median / 939 ms p95**, with **43/43** steady full-hop budget misses and **16.092 s p95 virtual playback delay** from accumulating backlog. Its 60 WAVs, history/output bounds, timeline gaps, 42 comparison-player links, and original hashes passed verification. The new listening page includes all five contexts without rerunning the previous four. Listening quality remains pending.
- The user selected SepFormer GPU/MPS acceleration before testing another trained streaming model. A [MPS replay](evaluation/MPS_SEPFORMER_EXPERIMENT.md) on Apple M5 used retained context 1,500 ms and new-audio hops 100/200 ms. MPS requires access outside this sandbox; GPU tensor execution was verified. SepFormer runs on MPS, ECAPA features on CPU and embedding layers on MPS, without unsupported-op CPU fallback. At hop 200 ms, steady processing was **190 ms median / 197 ms p95**, **3/107** steady blocks exceeded 200 ms, and virtual playback delay was **413 ms median / 424 ms p95**. Hop 100 ms overloaded (**216/216** steady budget misses; **15.526 s p95 virtual delay**). Two prefix probes preserved CPU/MPS outputs and mapping within the numerical guard. All 66 WAVs, 30 player links, frame accounting, playback gaps and original hashes passed verification. **The 200 ms hop meets the exploratory 500 ms virtual-delay target on this short recording only; listening quality, sustained operation and physical audio routing remain unverified.** It does not meet the PRD's provisional 150 ms wired target or become a trained causal model.
- Evaluation audio/data plus SepFormer and ECAPA inference weights use about **903 MiB**, including **38 MiB** of earlier live replay results, **102 MiB** for the rolling-context sweep, **50 MiB** for the 1,500 ms comparison and **59 MiB** for the MPS comparison, within the 3 GB storage cap. No full LibriMix corpus or WHAM noise was downloaded.
- The user accepted the listening quality of **MPS context 1,500 ms / hop 200 ms** on the local example. This resolves its listening-pending status for that example only; physical routing and sustained operation remain open.
- A [mixed-calibration enrollment experiment](evaluation/AUTO_ENROLLMENT_EXPERIMENT.md) creates anonymous profiles without separate enrollment files. On the existing Mix.wav, **only the first 10 s** supplied calibration; the disjoint **13.125 s suffix** supplied replay. Profile creation took **1.906 s**, warm-up **2.693 s**; automatic-profile replay processing was **184 / 187 ms p50 / p95**, with **403 ms p95 virtual playback delay** and **1/57** steady budget misses. A separate old-enrollment control reached **405 ms p95 delay**. Its stream assignment differed on **9/57, 18/57, and 17/57** steady windows for the three anonymous profiles, so automatic-enrollment identity/quality requires listening. Thirty-second real calibration and unknown speaker count are not validated: the checkpoint always supplies three candidates. Reusing persisted embeddings for only Speaker 01 + 03 on a 2.4 s excerpt reproduced the original pair exactly. Verification passed profile hashes, calibration-only samples, all output frame/timeline checks, 24 player links, silent/short input rejection, and corrupt-embedding rejection. Local artifacts added about **30 MiB**, within the 3 GB cap. No new datasets, models, or dependencies were downloaded.
- The [local website](local_web/README.md) is implemented and running on `http://127.0.0.1:8765`. [PRD.md](PRD.md) v0.4 is the single source of truth; [AGENTS.md](AGENTS.md) requires future work to read PRD/progress first. Browser AudioWorklet capture, loopback WebSocket, local model executor, calibration, reusable/selectable/renameable profiles, Stop, Bypass, volume, online limiting, bounded queues and JSON timing reports are implemented. **200 ms overloaded** in the web test; explicit **300 ms** is a comparison option retaining 1,500 ms context. Server checks completed 20/20 blocks for one/two speakers at 300 ms (p95 process ~245 ms), and 50/50 Bypass blocks at 20 ms. A Safari demo of 12.9 s completed at **601 ms p95 estimated application delay**, **253 ms process p95**, and 0 ms recorded playback gaps. This **does not meet <500 ms** and is not physical mic/AirPods delay. Exact 30 s calibration/profile creation passed with an accelerated repeated-audio fixture; no microphone was recorded during agent verification. [Verification](local_web/VERIFICATION.md) records all failures/limits, transport/control/security checks, and worklet sample-count tests. Live listening PCM is not saved; only explicitly captured calibration/profiles are stored locally. Actual mic permission/route, profile purity, 300 ms quality, mobile browser and sustained operation remain open.
